# Decision Escalation

Use this reference when a missing decision or external prerequisite affects the diagnosis or fix.

Ask when the answer changes correctness, product behavior, scope, or authorization and cannot be inferred from the request or available evidence. For example, two behaviors may both be technically valid but implement different product expectations.

A question may be needed before investigation begins. Do not require failed rounds, an Oracle consultation, or exhaustion of all possible tools first. Continue independent work while waiting when the runtime supports it.

Before asking, summarize the relevant observations and the concrete decision. Present only viable options, explain the tradeoff, and recommend one when the evidence supports it. Use the active runtime's user-input interface.

Do not ask again for actions already authorized. Do not treat unavailable optional tools as missing user intent. When access, hardware, or an external service blocks a check, state the limitation and complete the useful work that remains possible.

After the answer arrives, incorporate it into the same task. The choice establishes the desired behavior; it does not by itself prove the diagnosis.
