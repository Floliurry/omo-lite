# Clear intent: resolve genuine forks

Read this path when the desired outcome is clear, or the user explicitly requests
an interview. Apply the entry's approval and authority contract.

Explore discoverable repository/system facts before asking. Identify independently
meaningful outcomes and record them in the draft's Components section when useful;
a cohesive request need not be split. Ask only unresolved owner decisions or material
tradeoffs that the existing request and evidence do not settle.

For a question, explain the evidence gap and how the answer changes the plan; offer
a defensible recommendation when available. Use a short focused set rather than a
fixed interview script. A routine reversible choice within authority can use a stated
default; silence cannot approve a reserved outcome, public contract, data-semantic,
safety, irreversible or spend/risk decision.

Before the approval brief, establish scope, approach, applicable test/QA strategy,
relevant constraints and stable executable boundaries. Missing decisions may remain
explicit dependencies without blocking unrelated work. Do not manufacture budget,
scale or audience questions when the task and project already settle them.

Present the brief once, wait for meaningful approval, then follow full-workflow's
plan generation and any required Metis analysis. Selected dual review still applies;
clear intent neither selects nor waives it. Deliver the plan and permission gaps,
not implementation.
