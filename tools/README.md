# tools

`omo` 命令：读文件、搜索和运行命令，输出都有上限，并且会说明怎么拿到剩下的部分。

Codex 没有读文件的工具，命令的输出原样进入上下文，超过大约 10,000 个 token 才会被截断，而且只留开头和结尾，中间真正要看的部分可能正好被丢掉。`omo` 自己控制输出大小，每次都在 Codex 截断之前停下。

## 文件

| 文件 | 内容 |
| --- | --- |
| `omo.mjs` | 命令本身，只依赖 Node.js；`grep` 和 `glob` 还需要 PATH 上有 ripgrep（`rg`） |

安装脚本在 `~/.local/bin`（或 `--bin-dir` 指定的目录）写一个名为 `omo` 的小 shell 脚本，用来运行已安装版本里的 `omo.mjs`。同名文件如果不是安装脚本写的，会保持原样。

## 用法

| 命令 | 输出 |
| --- | --- |
| `omo read FILE [START-END \| START] [FILE [RANGE] ...]` | 带行号的文件内容。单个文件每次一页，约 8,000 个 token，末尾给出读下一页的命令；多个文件整份输出，放不下的留给下一条命令 |
| `omo grep [rg 选项] PATTERN [PATH...]` | 按文件分组的匹配行，最多 100 行；`-l` 改为列出文件和各自的匹配数；其他 `rg` 选项原样传递 |
| `omo glob [--hidden] [--no-ignore] PATTERN [DIR...]` | 匹配的文件路径，按路径排序，最多 100 个；默认跳过隐藏文件和被 `.gitignore` 忽略的文件 |
| `omo run [--grep REGEX] [--tail N] COMMAND...` | 先打印完整输出要保存到的文件路径，再运行命令，然后输出退出码、行数、匹配 `REGEX` 的行和最后 40 行；输出很短时整份打印 |

`omo run` 只给一个参数时交给 `bash -c` 运行，给多个参数时把第一个当作程序、其余当作它的参数；`--` 之后的内容都属于被运行的命令。

## 重复读取

在同一个 Codex 线程里（按 `CODEX_THREAD_ID` 区分），再读一段没改过的范围时，`omo read` 只输出一行提示，不再重复内容；加 `--again` 可以强制重新输出。读取记录放在临时目录的 `omo-reads/` 下，按文件的修改时间和大小判断是否改过。

上下文压缩之后，之前读出的内容已经不在上下文里，[`hooks/read-reset.mjs`](../hooks/README.md) 会清掉这个线程的读取记录，之后再读会照常输出。
